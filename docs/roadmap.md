## Що переглянуто проти `starland-business-logic.md`

| Було | Стало | Чому |
|---|---|---|
| BullMQ + Redis | QStash + Vercel Cron + transactional outbox | Воркер BullMQ вимагає постійного процесу, якого на Vercel немає |
| Два застосунки (`admin`, `portal`) | Три (`+api`) | Машинний вхід не має пробивати діру в Cloudflare Access перед адмінкою |
| Гнучкий RBAC — після MVP | Permission-based зі скоупами з першого дня | Вимога «view/edit доступи всюди» інакше не виражається; переробляти авторизацію потім дорожче вдесятеро |
| Медичні дані — усе шифрувати | Структуровані поля відкриті, вільний текст шифрований | За групою здоровʼя й алергіями потрібні фільтри та звіти |
| Кухня — єдина зовнішня інтеграція | Дві: сканер і кухня | Сканер виявився окремою системою замовника |

## Поза скоупом і чому

| Що | Причина |
|---|---|
| Офлайн-режим (PWA, IndexedDB, outbox на клієнті) | Перенесено на фазу після релізу |
| Мобільний застосунок | PWA частково закриє, коли дійде черга до офлайну |
| AI-модуль | Окремий сервіс поверх тих самих таблиць, не блокує базовий продукт |
| SMS | Telegram + email покривають потребу; SMS коштує грошей за повідомлення |
| Двосторонній чат у Telegram | Відповіді у вебі; вхідні повідомлення ускладнюють модерацію й шифрування |
| Пошук по повідомленнях | Конфліктує з шифруванням вмісту; замість нього — перевірка стоп-слів до шифрування |
| OAuth-синхронізація Google Calendar | ICS-фід працює в Google, Apple і Outlook без OAuth і без ризику зіпсувати чужий календар |
| Офіційні бланки звітності МОН | Замовник підтвердив: власні зручні формати |
| ІПР та інклюзивна документація | Велика окрема підсистема, окрема фаза |

## Порядок роботи над новою фазою

1. Перечитати відповідний розділ спеки й рядки цієї таблиці.
2. Уточнити те, що позначене відкритим.
3. Написати план у `docs/plans/YYYY-MM-DD-<фаза>.md` у форматі Т1.
4. Виконати задачі окремими агентами з ревʼю між ними.
5. Оновити статус фази тут.
