# Starland — єдина сторінка «Користувачі» з вкладками замість трьох окремих списків

**Goal:** зараз є три окремі спискові сторінки — `/users` (AppUser),
`/students` (Student), `/staff` (Employee) — кожна свій пункт у сайдбарі,
свій `page.tsx`, свій permission-gate. Директор хоче один компактний вхід:
`/users` з вкладками **Всі користувачі / Вчителі / Учні / Інші**, а
`/students` і `/staff` як окремі маршрути зникають. Профільні модалки
(`PersonModalProvider`, `usePersonModal`) не змінюються — вони вже не
прив'язані до жодного роуту.

**Рішення (підтверджено користувачем):**
- «Вчитель» визначається роллю (`user_roles` → `roles.code = 'teacher'`,
  `revoked_at IS NULL`), не посадою і не викладацьким призначенням.
- Кожна вкладка лишає свій набір колонок — переносимо `UsersTable` /
  `StudentsTable` / `StaffTable` як є, без уніфікації колонок.
- «Інші» = колишня сторінка `/staff` цілком (весь `Employee`, включно з тими,
  хто одночасно вчитель — вкладки навмисно перетинаються за змістом, це вже
  так між `/users` і `/staff` сьогодні).
- Вкладка не рендериться, якщо немає відповідного permission
  (`users.read` → Всі/Вчителі, `students.read` → Учні, `staff.read` → Інші).
  Немає жодного з трьох → `redirect('/')`, як і сьогодні для `/users`,
  `/staff`. Активна вкладка за замовчуванням — перша дозволена.
- Перемикання вкладки скидає `page`/`q`/`sort`/`dir` (кожна вкладка — інший
  запит, змішувати пагінацію/сортування між ними немає сенсу).
- Статистичні картки (Всього/Активні/Персонал/Нові) лишаються тільки на
  вкладці «Всі користувачі» — не дублюються, це і є «компактно».

## Обсяг змін

1. `packages/i18n/src/uk.ts` — `uk.users.tabs.{all,teachers,students,other}`.
2. `nav-config.ts` — `NavItem.permissionCode: string | string[] | null` (any-of
   для масиву); один пункт `Користувачі → /users` замість трьох.
   `visible-nav-items.ts` — підтримати масив.
3. `students/students-table.tsx`, `staff/staff-table.tsx` — `basePath`
   пагінації `/students`/`/staff` → `/users` (сторінка тепер тільки одна).
4. Новий маленький серверний компонент — рядок вкладок як звичайні `<Link>`
   (той самий підхід, що й `DataTablePagination`: URL рулить станом, без
   клієнтського JS/Radix Tabs context), стилізований під наявний
   `components/ui/tabs.tsx`.
5. `users/page.tsx` — зливає тіла сьогоднішніх `users/page.tsx`,
   `students/page.tsx`, `staff/page.tsx`: рахує дозволи → визначає активну
   вкладку → виконує **тільки її** запит (не всі чотири одразу — інакше
   регресія в той самий "модалка довго грузиться" клас багів) → рендерить
   заголовок з дією "Додати", що відповідає активній вкладці, і саму таблицю.
   Вкладка «Вчителі» = запит `users/page.tsx` + додатковий фільтр
   `id IN (userIds з активним teacher-UserRole)`.
6. Видалити `students/page.tsx`, `staff/page.tsx` (файли-роути; решта
   `students/*`, `staff/*` лишається — використовується модалками й новою
   `users/page.tsx`).
